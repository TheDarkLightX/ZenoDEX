\section{Purpose}
This appendix is the audit companion to the main public whitepaper. Its job is
to pin each major public claim family to concrete repo-local artifacts.

The governing evidence rule is
\[
\mathtt{proved} > \mathtt{contract} > \mathtt{implemented} > \mathtt{replay\_backed} > \mathtt{hypothesis}.
\]
Plain English: the tables below are claim-to-artifact maps, not marketing
summaries.
Practical consequence: a reviewer can audit the public package without relying
on non-public development notes or unpublished implementation tooling details.

\section{Reference algorithm skeletons}
\paragraph{A. Canonical bounded route selection.}
\[
\Winner(C) := \argmin_{c \in C} \Key(c).
\]
Plain English: once a bounded candidate family is emitted, the chosen route
is the unique minimum under the explicit total key.
Practical consequence: public runtime selectors should be audited as
certificate-carrying argmin procedures rather than loop-order heuristics.

Operational skeleton:
\begin{enumerate}
  \item emit a bounded candidate family $C$ from the current admitted route domain;
  \item compute the explicit runtime key for each candidate;
  \item select $w = \Winner(C)$;
  \item build the route certificate or packet around $w$;
  \item expose the result as canonical only when the guarded packet verifies.
\end{enumerate}

\paragraph{B. Settlement packet composition.}
\[
\mathsf{packet\_ok} \leftrightarrow \mathsf{strong\_certificate\_ok} \wedge \mathsf{value\_lane\_ok} \wedge \mathsf{provenance\_ok}.
\]
Plain English: an end-to-end settlement packet is accepted only when each
constituent lane verifies and the bundle remains coherent.
Practical consequence: settlement bundling is fail-closed composition, not
best-effort aggregation.

Operational skeleton:
\begin{enumerate}
  \item build the strong settlement certificate on the canonical delta table;
  \item attach value-lane and provenance packet material;
  \item serialize the combined packet;
  \item verify the packet by re-checking each component gate and the bundle-level shell.
\end{enumerate}

\paragraph{C. Runtime release replay.}
\[
\mathsf{ReleaseClaimOK} := \mathsf{CleanTree} \wedge \mathsf{ScopeFrozen} \wedge \mathsf{ReplayGreen} \wedge \mathsf{ExclusionsHonest}.
\]
Plain English: the public release claim is valid only on a clean tree with a
frozen documented scope and green replay lanes.
Practical consequence: the release process is itself a public artifact, not only
a private operator habit.

Primary public replay entry points are:
\begin{itemize}
  \item \code{python3 tools/permissionless_assurance.py status}
  \item \code{python3 tools/permissionless_assurance.py replay public}
  \item \code{python3 tools/permissionless_assurance.py replay critical}
  \item \code{python3 tools/permissionless_assurance.py replay full}
\end{itemize}

\section{How to read the claim boundary}
The public package uses a three-level distinction:
\[
\mathsf{FullTargetArchitecture} \supset \mathsf{CurrentPublicEvidenceFrontier} \supset \mathsf{CurrentRC1Claim}.
\]
Plain English: the complete intended architecture is broader than the public
evidence frontier, and the evidence frontier is broader than the current RC1
public claim.
Practical consequence: the appendix helps reviewers see exactly which artifacts
support which class of claim today.
