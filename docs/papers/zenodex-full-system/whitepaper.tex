\begin{abstract}
ZenoDEX is intended to be a proof-carrying exchange architecture rather than a collection of ad hoc trading or settlement scripts. The complete system spans theorem-bearing spot kernels, certificate-carrying settlement and price-provenance planes, kernel-composition contracts, bounded stablecoin and perpetual-risk slices, narrow runtime ingress boundaries, and advisory automation that remains structurally non-authoritative. This whitepaper states the intended full system, the current evidence frontier, the narrower current RC1 public claim surface, and the remaining proof agenda required to close the gap between them.
The newest proof layer adds a mechanism-generic settlement theorem and a mistake-proofing theorem: any mechanism that supplies exact generator coverage, a certified winner, feasibility, and trace realization inherits canonical safe settlement, while dangerous user actions may enter the submit path only through an explicit interlock.
\end{abstract}

\paragraph{Contributions.}
This whitepaper contributes:
\begin{enumerate}
  \item a full-system decomposition of ZenoDEX into execution, guard, certificate, risk, runtime, and assurance planes;
  \item an explicit evidence discipline for separating proved, contract-backed, implemented, tested-discovery, and hypothetical claims;
  \item the global settlement-algebra theorem schema tying runtime candidate generation, winner certificates, and trace realization to canonical safe settlement;
  \item the Poka-yoke safety theorem tying dangerous status classes to explicit user interlocks;
  \item a guarantee-and-assumption matrix for the main protocol surfaces;
  \item an artifact and algorithm map that ties paper claims back to concrete repo-local files.
\end{enumerate}

\section{Execution plane and theorem-bearing spot core}
The strongest current theorem stock lives in the bounded spot core.

\subsection{Canonical winner semantics}
The central selection law is
\[
C \neq \varnothing \to \exists !\, w \in C \text{ such that } \forall c \in C,\; \Key(w) \le \Key(c).
\]
Standard reading: every admitted nonempty candidate family with a total key has a unique canonical winner.
Practical consequence: canonicality is a semantic property, not merely a stable sort artifact.

\begin{claim}[Current strongest spot theorem posture]
For the promoted exact-in routing and batch-clearing slices, the repository already contains Lean-backed winner theorems strong enough to justify canonical-winner claims on the emitted bounded candidate families.
\end{claim}
\paragraph{Proof idea.}
The current Lean files prove unique canonical minima for finite batch candidate sets and prove the exact-in ranked-witness shell that transports route-key order into certificate structure. This does not yet prove universal optimality over every conceivable route family; it proves canonicality over the actual bounded emitted candidate family.

\subsection{CPMM safety and fee conservation}
The local AMM safety envelope is shaped by
\[
\mathsf{amount\_out} < \mathsf{reserve\_out},
\qquad
K_{after} \ge K_{before}\;\text{(zero-fee integer model)},
\]
and the fee-side conservation posture is
\[
\mathsf{fee\_conserved} \wedge \mathsf{dust\_carry\_bounded}.
\]
Standard reading: spot safety depends on reserve-bounded swaps, local invariant structure, and explicit dust state when exact fee conservation matters.
Practical consequence: higher-level routing and batch correctness should be stated only over states that already satisfy these local preconditions.

\section{Certificate, settlement, and composition planes}
ZenoDEX is intended to move from state transitions to witness-carrying transitions.
The settlement composition law is
\[
\mathsf{SettlementOK}
\to \mathsf{CanonicalDeltaTable}
\wedge \mathsf{QuoteOrKernelWitnessBound}
\wedge \mathsf{ReplayVerifiable}.
\]
Standard reading: a settlement object is meaningful only if its deltas are canonical, its fills are witness-bound, and the packet can be replay-verified.
Practical consequence: settlement should be read as a certificate plane rather than a post hoc report.

\subsection{Settlement algebra and global mechanism theorem}
The underlying additive settlement object remains the same small algebra:
\[
\mathsf{Settlement} := \mathbb{Z}\times\mathbb{Z},
\qquad
(\Delta x_1,\Delta y_1)\circ_s(\Delta x_2,\Delta y_2)
:=(\Delta x_1+\Delta x_2,\Delta y_1+\Delta y_2),
\]
with scalar net-flow map
\[
\Delta(\Delta x,\Delta y):=\Delta x+\Delta y.
\]
Standard reading: a two-asset settlement is a signed reserve delta pair, settlements compose by componentwise addition, and $\Delta$ is the scalar net-flow homomorphism.
Practical consequence: this algebra is useful for certificate composition and replay, but scalar net-flow is not an economic value invariant because it adds unlike token units.

The newer result is not a change to that algebra. It is a global theorem schema
for mechanisms that want to reuse the canonical settlement proof. A mechanism
$M$ exposes a finite feasible domain, an emitted runtime key list, a selected
candidate, and the trace actually executed. The obligation bundle is
\[
\begin{aligned}
&\mathsf{GeneratorExact}(M)
\wedge \mathsf{WinnerCertified}(M)
\wedge \mathsf{WinnerFeasible}(M)\\
&\wedge \mathsf{TraceRealizesWinner}(M)
\to \mathsf{CanonicalSafeSettlement}(M).
\end{aligned}
\]
Standard reading: if the emitted list is exactly the feasible key image, the
selected candidate is certified as the winner of that list, the selected key is
feasible, and the runtime trace realizes that selected candidate, then the trace
executes the canonical safe settlement for $M$.
Practical consequence: CPMM batches, route selection, orderbook settlement,
perp settlement, and future DEX mechanisms do not need to reprove the canonical
settlement theorem from scratch; they must prove that they instantiate this
interface.

The conclusion is not a vague safety label. In the current Lean theorem it
expands to:
\[
\begin{gathered}
S_M:=\mathsf{feasibleKeys}(M),\quad
A_M:=\pi_1(\mathsf{batchAB}(M.\mathsf{trace})),\quad
B_M:=\pi_2(\mathsf{batchAB}(M.\mathsf{trace})).
\end{gathered}
\]
\[
\begin{aligned}
\mathsf{CanonicalSafeSettlement}(M)
:\!\!\Longleftrightarrow\;&
\mathsf{batchToSettlement}(M.\mathsf{trace})
  =\mathsf{batchToSettlement}(M.\mathsf{selected.batch})\\
&\wedge\ M.\mathsf{selected.key}\in S_M\\
&\wedge\ \forall x\in S_M,\; A_M\ge \mathsf{vol}(x)\\
&\wedge\ \forall x\in S_M,\;
  A_M=\mathsf{vol}(x)\to B_M\ge \mathsf{sur}(x)\\
&\wedge\ \forall x\in S_M,\;
  A_M=\mathsf{vol}(x)\to B_M=\mathsf{sur}(x)\\
&\hspace{35mm}\to M.\mathsf{selected.order}\le \mathsf{ord}(x).
\end{aligned}
\]
Standard reading: the executed trace has the selected settlement, the selected
key is feasible, and the trace is lexicographically maximal by volume, then
surplus, with minimum order among exact ties over the feasible key image.

The proof-carrying bridge has the concrete certificate shape
\[
\mathsf{ListCertificateOK}(L,w)
\leftrightarrow
w\in L \wedge \forall x\in L,\; w\le x,
\]
and the generator audit shape
\[
L.\mathsf{toFinset} = \mathsf{image}(\mathsf{keyOf},D).
\]
Standard reading: the winner is a member of the emitted candidate-key list and
is minimal under the explicit key; after deduplication, the emitted list equals
the image of the feasible domain.
Practical consequence: the runtime search is not trusted as an optimizer. It is
trusted only to emit replayable evidence that the Lean theorem can check.

The composition law across kernels is the mirror-sync discipline:
\[
\mathsf{SharedFactInA} = \mathsf{MirrorOfFactInB}
\quad\text{must hold inductively under each reserve-affecting or stake-affecting step.}
\]
\begin{claim}[Composition invariant]
Composable kernel invariants remain inductive only when shared reserve and stake mirrors are synchronized after every transition that can change the source fact.
\end{claim}
\paragraph{Proof idea.}
Without synchronized mirrors, a downstream guard reasons over stale pre-state. With explicit mirror wiring and system invariants, inductiveness is restored.

The value and oracle packet side is similarly explicit:
\[
\mathsf{AssetConserved} \wedge \mathsf{ExplicitNonnegativePrices} \to \mathsf{NetSpotValue}=0,
\]
\[
\mathsf{PricePacketAdmissible}
\leftrightarrow \mathsf{UniqueAssetSet} \wedge \mathsf{PositivePrices} \wedge \mathsf{FreshEnough} \wedge \mathsf{SyncGateGreen}.
\]
Standard reading: value-neutrality and price provenance are explicit contract surfaces with explicit assumptions.
Practical consequence: the whitepaper can state these guarantees precisely instead of vaguely claiming ``oracle safety.''

\section{Risk planes: zUSD, perps, and advisory automation}
The full architecture includes monetary and derivatives layers even though their proof maturity differs from the spot core.

The intended zUSD invariant is
\[
\mathsf{zUSDAdmissible} \to \mathsf{DebtConservation} \wedge \mathsf{CollateralConservation},
\]
with a stale-oracle barrier of the form
\[
\mathsf{price\_pending} \neq \mathsf{price} \to \mathsf{RiskyTransitionsBlocked}.
\]
For perps, the intended posture is
\[
\mathsf{PerpSettlementAdmissible}
\to \mathsf{FreshOracleWindow}
\wedge \mathsf{BoundedMoveGate}
\wedge \mathsf{FundingWitnessLaneValid}.
\]
Standard reading: the monetary and derivatives slices are bounded by explicit oracle freshness and settlement-witness conditions.
Practical consequence: these layers belong in the whole-system architecture, but they are not yet as mature as the theorem-bearing spot core.

Automation is present but bounded by a strict trust law:
\[
\mathsf{KRR} \to \mathsf{AdvisoryOnly},
\qquad
\neg(\mathsf{KRR} \to \mathsf{ExecutionAuthority}).
\]
Standard reading: KRR may rank checks and summarize trust posture, but it never becomes a value-moving authority.
Practical consequence: the system can include advisory intelligence without collapsing the core correctness boundary.

\subsection{Poka-yoke safety contract}
The mistake-proofing layer is formalized as a fail-closed submit predicate. For
a risk status $r$ and interlock state $i$,
\[
\mathsf{submitAllowed}(r,i)=\mathsf{true}
\Longleftrightarrow
(\mathsf{dangerous}(r)=\mathsf{false})
\vee(\mathsf{interlockSatisfied}(i)=\mathsf{true}),
\]
where
\[
\begin{aligned}
\mathsf{interlockSatisfied}(i)=\mathsf{true}
\Longleftrightarrow\;&
\mathsf{interlockPresent}(i)=\mathsf{true}\\
&\wedge\bigl(\mathsf{typedConfirmAccepted}(i)=\mathsf{true}\\
&\qquad\vee\ \mathsf{advancedOverrideLogged}(i)=\mathsf{true}\bigr).
\end{aligned}
\]
The Lean theorem is
\[
\mathsf{submitAllowed}(r,i)=\mathsf{true}
\to
\mathsf{Shielded}(r,i).
\]
The shielded predicate expands to
\[
\begin{aligned}
\mathsf{Shielded}(r,i)
:\!\!\Longleftrightarrow\;&
\mathsf{dangerous}(r)=\mathsf{false}\\
&\vee\ \mathsf{interlockPresent}(i)=\mathsf{true}
\wedge\bigl(\mathsf{typedConfirmAccepted}(i)=\mathsf{true}\\
&\qquad\vee\ \mathsf{advancedOverrideLogged}(i)=\mathsf{true}\bigr).
\end{aligned}
\]
Standard reading: if a submit is allowed, then either the action is not
dangerous or an explicit interlock exists and was satisfied by typed
confirmation or a logged advanced override.
Practical consequence: the user-interface and audit tools can add new failure
modes without weakening the safety contract, provided each dangerous mode has a
visible signal and a submit interlock.

The runtime audit report mirrors the theorem with the obligation
\[
\mathsf{signal\_present}\wedge\mathsf{interlock\_present}
\]
for every catalogued dangerous failure mode. The current audit contract is
replayable through \code{tools/pokayoke/pokayoke_audit.py}; it fails closed if a
catalogued mode is signal-only, interlock-only, or uncovered.

\section{Reference algorithm skeletons}
The whitepaper should expose the control flow of the main bounded procedures as well as their supporting artifacts.

\paragraph{A. Canonical bounded route selection.}
\[
\Winner(C) := \argmin_{c \in C} \Key(c).
\]
Operational skeleton:
\begin{enumerate}
  \item emit a bounded candidate family $C$ from the current admissible route domain;
  \item compute the explicit runtime key for each candidate;
  \item select $w = \Winner(C)$;
  \item build the certificate / projection / guarded quote packet around $w$;
  \item expose the quote as canonical only when the guarded packet verifies.
\end{enumerate}
Primary artifacts:
\begin{itemize}[nosep,leftmargin=6mm]
  \item \code{lean-mathlib/Proofs/ZenoDEXExactInTrueKeyWinner.lean}
  \item \code{src/integration/exact_in_route_certificate.py}
  \item \code{src/integration/tau_witness.py}
\end{itemize}

\paragraph{B. Settlement end-to-end certificate build.}
\[
\mathsf{packet\_ok} \leftrightarrow \mathsf{strong\_certificate\_ok} \wedge \mathsf{feature\_extension\_ok} \wedge \mathsf{value\_lane\_ok}.
\]
Operational skeleton:
\begin{enumerate}
  \item build the strong settlement certificate on the canonical delta table;
  \item attach the feature-extension packet and chosen value lane;
  \item attach provenance or signed-attestation inputs as required;
  \item serialize the packet;
  \item verify the bundle-level shell by re-checking each component gate.
\end{enumerate}
Primary artifacts:
\begin{itemize}[nosep,leftmargin=6mm]
  \item \code{src/integration/settlement_end_to_end_certificate_packet.py}
  \item \code{src/kernels/dex/settlement_end_to_end_certificate_packet_v1.yaml}
  \item \code{lean-mathlib/Proofs/ZenoDEXSettlementEndToEndCertificatePacket.lean}
\end{itemize}

\paragraph{C. Global mechanism settlement acceptance.}
\[
\mathsf{AcceptedByFamily}(F,M)
\to
\mathsf{CanonicalSafeSettlement}(M).
\]
Operational skeleton:
\begin{enumerate}
  \item define the mechanism's feasible domain $D$ and key function $\mathsf{keyOf}$;
  \item emit the runtime candidate-key list $L$;
  \item prove $L.\mathsf{toFinset}=\mathsf{image}(\mathsf{keyOf},D)$;
  \item prove the selected key is list-minimal and feasible;
  \item prove the executed trace realizes the selected candidate;
  \item apply the global settlement theorem.
\end{enumerate}
Primary artifacts:
\begin{itemize}[nosep,leftmargin=6mm]
  \item \code{lean-mathlib/Proofs/SettlementCanonicalExecution.lean}
  \item \code{lean-mathlib/Proofs/SettlementMechanism.lean}
\end{itemize}

\paragraph{D. Poka-yoke submit gate.}
\[
\mathsf{dangerous}(r)=\mathsf{true}
\wedge \mathsf{interlockSatisfied}(i)=\mathsf{false}
\to
\mathsf{submitAllowed}(r,i)=\mathsf{false}.
\]
Operational skeleton:
\begin{enumerate}
  \item classify the current action into a risk status;
  \item render a user-visible signal for each dangerous status;
  \item require a typed confirmation or logged advanced override before submit;
  \item emit an audit report requiring both signal and interlock coverage for every catalogued mode.
\end{enumerate}
