\begin{abstract}
Zeno Oracle is a proof-carrying oracle layer for ZenoDEX-critical reads.
Its core design principle is that a consumer should not accept an oracle value
merely because a service returned it. A consumer should accept a value only when
a replayable artifact proves that the value passed the declared feed, reporter,
source-diversity, aggregation, freshness, uncertainty, and consumer-profile
checks. The current devnet alpha implements reporter registration, feed
registration, signed report submission, admitted median aggregation, read
receipt generation, ZenoDEX adapter bridge generation, economic event receipts,
and replay from a persisted event log. This paper gives the mathematical
contract, verifier design, current evidence boundary, and remaining production
work.
\end{abstract}

\section{Motivation}

Oracle failures are not only wrong-price failures. They also include stale
reports, unverifiable reports, source correlation, policy downgrades, receipt
borrowing across consumers, replay drift, unbounded uncertainty, reward
overspending, and consumer-side bypasses. A conventional API-oriented oracle
integration can accidentally turn these into hidden assumptions.

Zeno Oracle exposes those assumptions as explicit artifacts. The target safety
shape is
\[
  \mathsf{AcceptedOracleUse}
  \Rightarrow
  \mathsf{DeclaredOraclePolicySatisfied}.
\]
This does not prove that a reported price is objectively true. It proves that a
critical consumer only used an oracle value after the declared safety contract
was checked.

\section{System Model}

Let \(C(x)\) denote canonical JSON serialization of an artifact \(x\), and let
\[
  H(x) := \texttt{sha256:} \parallel \mathrm{SHA256}(C(x)).
\]
Most Zeno Oracle objects carry an identifier field such as
\texttt{feed\_id}, \texttt{submission\_id}, \texttt{aggregate\_id}, or
\texttt{bridge\_id}. For an object \(x\) with identifier field \(id\), the
verifier checks
\[
  x.id = H(x \setminus \{id\}).
\]
Any mutation to a serialized semantic field changes the expected identifier
and causes verifier rejection.

The devnet service stores accepted artifacts under hash-derived filenames and
appends event receipts to \texttt{events.jsonl}. A live state is intended to be
replayable from
\[
  \mathsf{event\ log} + \mathsf{referenced\ artifacts}.
\]
Replay currently rejects when a referenced artifact is missing. A production
replay kernel should also re-run every referenced verifier and compare all
artifact hashes.

\section{Feed Registry}

A feed registry is a versioned set of active feeds. Each feed contains a query
specification, a source-diversity policy, and an aggregate policy. For the
current price-feed shell, a query specification is restricted to
\[
\begin{aligned}
  \mathsf{query\_kind} &= \texttt{price\_e8},\\
  \mathsf{unit} &= \texttt{quote\_per\_base},\\
  \mathsf{value\_scale} &= 10^8,\\
  \mathsf{base\_asset} &\neq \mathsf{quote\_asset}.
\end{aligned}
\]
The aggregate policy declares the aggregation schema, report schema, evidence
floor, reporter quorum, source quorum, freshness window, and maximum deviation
in basis points. A feed is rejected when any hash, active-status,
evidence-floor, quorum, freshness, deviation, or uniqueness check fails.

\section{Source Diversity}

For a source set \(S\), the verifier counts distinct operators, venues, data
families, transports, and jurisdictions. It also checks concentration limits:
\[
\begin{aligned}
  \mathrm{DistinctOperators}(S) &\geq m_o,\\
  \mathrm{DistinctVenues}(S) &\geq m_v,\\
  \mathrm{DistinctFamilies}(S) &\geq m_f,\\
  \mathrm{DistinctTransports}(S) &\geq m_t,\\
  \mathrm{DistinctJurisdictions}(S) &\geq m_j,\\
  \mathrm{MaxSameClass}(S) &\leq M.
\end{aligned}
\]
This proves compliance with the declared classification rule. It does not
prove real-world independence or source honesty.

\section{Signed Reports}

A signed report submission contains a reporter id, reporter BLS public key,
chain id, and one or more reports. Each report contains a query id, source id,
value, observed epoch, sequence, previous-report id, payload hash, signature,
and report id.

The signed payload is the canonical serialization of the domain-separated
report fields. The verifier checks
\[
\begin{aligned}
  \mathsf{payload\_hash} &= H(\mathsf{payload}),\\
  \mathsf{Verify}_{BLS}(\mathsf{pubkey}, \mathsf{domain} \parallel \mathsf{payload},
  \mathsf{signature}) &= \mathsf{true},\\
  \mathsf{report\_id} &= H(\mathsf{report} \setminus \{\mathsf{report\_id}\}).
\end{aligned}
\]
It also checks sequence-chain continuity and previous-report links. Signature
acceptance proves key possession over the exact payload. It does not prove
reporter honesty.

\section{Reporter Lifecycle and Admission}

Reporter lifecycle traces model registration, bond deposits, report
submission, disputes, slashes, dispute resolution, unregistration, and bond
withdrawal. A reporter is admissible only when the lifecycle trace proves the
reporter is active and sufficiently bonded at submission time.

For a signed report \(r\), lifecycle trace \(L\), source policy \(S\), current
epoch \(t\), and freshness window \(w\), the admission predicate is
\[
\begin{aligned}
\mathsf{Admit}(r,L,S,t,w) :=\;&
  \mathsf{SignedReportAccepted}(r)\\
  &\land \mathsf{LifecycleSubmitMatches}(L,r)\\
  &\land \mathsf{ReporterActiveAndBonded}(L,r.\mathsf{reporter\_id})\\
  &\land r.\mathsf{source\_id} \in S\\
  &\land r.\mathsf{query\_id} = S.\mathsf{query\_id}\\
  &\land r.\mathsf{observed\_epoch} \leq t\\
  &\land t-r.\mathsf{observed\_epoch} \leq w.
\end{aligned}
\]
The devnet service uses this bridge when accepting signed report submissions.
Signed but unregistered, stale, future, wrong-query, wrong-source, or
unbonded reports are rejected before they can enter an aggregate.

\section{Median Aggregation and Uncertainty}

The current admitted aggregate is \(\mathsf{median\_3}\): exactly three
admitted reports from distinct reporters and distinct sources for the same
query. Given admitted values \(x_1,x_2,x_3>0\), the aggregate value is
\[
  m := \mathrm{median}(x_1,x_2,x_3).
\]
The confidence radius is
\[
  c := \max_i |x_i - m|,
\]
and the uncertainty in basis points is
\[
  \mathsf{deviation\_bps} := \left\lceil \frac{10000c}{m} \right\rceil.
\]
The aggregate is accepted only when
\[
  \mathsf{deviation\_bps} \leq \mathsf{max\_deviation\_bps}.
\]
A price is high uncertainty when the reported spread around the median exceeds
the feed's declared deviation budget, or when a consumer profile requires a
tighter uncertainty budget than the aggregate supplies. For critical actions,
high uncertainty is a rejection condition, not a warning.

\section{Read Receipts and Consumer Binding}

An aggregate read bridge converts an accepted aggregate into a consumer-readable
receipt bundle. The value hash commits to the aggregate id, query id, value,
confidence radius, deviation, observed epoch, report count, and admission
count. The bridge then creates a read receipt and a consumer-action receipt
that depends on the read receipt.

A ZenoDEX consumer should not merely ask whether a read exists. It should ask
whether the read is authorized for this exact action. The aggregate-adapter
bridge binds
\[
  \mathsf{aggregate\_read},\quad \mathsf{action},\quad \mathsf{consumer\_profile}.
\]
For critical actions, the profile pins the consumer module, action kind, query
id, evidence floor, maximum freshness window, and criticality bit. This closes
the receipt-borrowing shape: a valid read for one query, module, action, value,
epoch, or profile cannot be silently reused for a different critical action.

\section{Devnet Service}

The devnet service is a transport layer around verifier kernels:
\[
  \mathsf{HTTPAccepted}
  \Rightarrow
  \mathsf{VerifierAccepted}
  \Rightarrow
  \mathsf{ArtifactPersisted}
  \Rightarrow
  \mathsf{EventReceiptAppended}.
\]
It exposes:
\begin{itemize}[leftmargin=*]
  \item \texttt{GET /health}
  \item \texttt{GET /state}
  \item \texttt{POST /reporters/register}
  \item \texttt{POST /feeds/register}
  \item \texttt{POST /reports/submit}
  \item \texttt{POST /aggregates/build}
  \item \texttt{GET /reads/latest?query\_id=...}
  \item \texttt{GET /adapter/latest?query\_id=...}
  \item \texttt{POST /economics/event}
  \item \texttt{POST /replay}
\end{itemize}
The event append path is serialized by a service lock so concurrent requests
inside one process cannot assign the same event sequence.

\section{Economic Security Envelope}

The current economic security shell verifies local budget arithmetic rather
than a live token economy. It enforces
\[
\begin{aligned}
  \mathsf{query\_reward\_paid} &\leq \mathsf{query\_budget\_remaining},\\
  \mathsf{reporter\_slash\_paid} &\leq \mathsf{reporter\_bond\_available},\\
  \mathsf{dispute\_slash\_paid} &\leq \mathsf{dispute\_bond\_available},\\
  \mathsf{reporter\_fee\_share}
  + \mathsf{treasury\_fee\_share}
  + \mathsf{burn\_fee\_share}
  &\leq \mathsf{fee\_paid}.
\end{aligned}
\]
This is the fail-closed budget layer. It does not yet prove optimal
tokenomics, oracle-token valuation, or game-theoretic equilibrium.

\section{Current Safety Statements}

The current implementation supports the following verifier-backed statements:

\begin{enumerate}[leftmargin=*]
  \item \textbf{Content mutation rejection.} If an accepted object uses a
  content-addressed identifier, then changing any serialized semantic field
  without recomputing the identifier causes verifier rejection.
  \item \textbf{Signed payload binding.} If a signed report submission is
  accepted, every accepted report signature verifies over the exact canonical
  payload fields used to compute the payload hash.
  \item \textbf{Admission safety.} If a report admission is accepted, then the
  signed report, lifecycle submit event, source-diversity policy, query id,
  payload hash, and freshness window are mutually consistent.
  \item \textbf{Median correctness.} If an admitted median3 aggregate is
  accepted, then its value, confidence, deviation, observed epoch, reporter
  count, source count, and deviation-policy check are derived from exactly
  three admitted reports.
  \item \textbf{Consumer binding.} If an aggregate-adapter bridge is accepted,
  then the downstream action facts match the accepted read bundle and are no
  weaker than the declared consumer profile.
  \item \textbf{Budget non-overspend.} If a budget transition is accepted, then
  reward, slash, dispute, and fee-split spends do not exceed their declared
  envelopes.
  \item \textbf{Devnet replay reference integrity.} If devnet replay accepts,
  every event-log artifact reference observed by the replay command resolves
  to a file in the devnet store.
\end{enumerate}

\section{Evidence Frontier}

As of the devnet-alpha gate, the public replay surface includes:
\[
\begin{array}{rl}
\mathsf{oracle\_chaos\_case\_count} &= 283,\\
\mathsf{oracle\_chaos\_rejected\_count} &= 283,\\
\mathsf{oracle\_chaos\_failed\_count} &= 0,\\
\mathsf{oracle\_pytest\_count} &= 275,\\
\mathsf{devnet\_alpha\_criteria} &= 12/12.
\end{array}
\]
The devnet-alpha audit exercises local service startup, three reporter
registrations, three signed report submissions over HTTP, feed registry
persistence, admitted median aggregate construction, read API exposure,
ZenoDEX adapter bridge generation, economic reward event persistence, replay
from stored receipts, CI wiring, public documentation, and devnet package
receipt generation.

\section{Limitations}

The devnet alpha does not claim production oracle truth, public on-chain feed
governance, a production oracle token, production code signing, real-world
source honesty, complete Byzantine fault tolerance, final tokenomics, or full
replay equivalence under arbitrary crash-consistency failures.

\section{Production Roadmap}

The next technical milestones are:
\begin{enumerate}[leftmargin=*]
  \item Stateful disaster-sequence fuzzing for the HTTP service and replay
  store.
  \item Replay strengthening: re-verify every referenced artifact and compare
  live state to replayed state.
  \item Higher-redundancy aggregation beyond \(\mathsf{median\_3}\).
  \item Public feed-governance rules for source classification, feed upgrades,
  and policy downgrades.
  \item Production reporter economics: bond sizing, dispute incentives, reward
  budgets, slash rules, and concentration caps.
  \item Production code signing and platform-native binaries.
  \item Lean or SMT proofs for median/deviation arithmetic, budget
  non-overspend, and replay state equivalence.
\end{enumerate}
