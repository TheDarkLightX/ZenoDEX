# FCIS M6 H01: Durable Retraction Publication-Atom Table Matrix

This document freezes the logical table boundary needed to refine the
research-only durable-retraction model into a datastore adapter. It is a
field-to-column contract, not a production SQL schema. The authoritative
research source is
`src/core/fcis_durable_retraction.py` at the H01 source head:

```text
commit: 476ec022e755ff049c39bf9f08c6606ac87532ca
tree:   a1d495eae0b26a369487ceb48cad5472abec74db
```

The source remains explicitly research-only and unmounted
(`src/core/fcis_durable_retraction.py:1-29`). A future adapter must implement
these relations and then supply independent transaction, crash, concurrency,
and configuration evidence.

## Authority rule

The logical relation has one semantic source for each value. A value repeated
in a foreign-key, index, cache, or evidence row is a checked projection. It is
never an alternate authority. A reopen succeeds only when all physical rows,
their canonical order, their closed types, and their derived projections equal
the complete canonical reconstruction.

The matrix uses these terms:

| Role | Meaning |
| --- | --- |
| `canonical-column` | The one logical column from which the value is read as an authoritative input to reconstruction. |
| `checked-projection` | A deterministic row/column projection generated from a canonical value and compared during reopen. |
| `derived-root` | A digest computed from the complete canonical layout; a stored cache is accepted only after recomputation. |

## Logical table inventory

| Logical table | Canonical contents | Key and closed-boundary requirements |
| --- | --- | --- |
| `snapshot_meta` | One durable snapshot header: `genesis_state_root`, deployment context, verifier context, current-state cache, and snapshot-root cache. | Exactly one row. Roots are 32-byte digests encoded as 64 lowercase hex characters in the model. `current_state_root` and `snapshot_root` are checked projections/caches, never caller-selected authority. |
| `authority_epochs` | One row per `AuthorityStateV1` except its writer-set collection. | Primary key `epoch_index`; indices are contiguous from zero. `phase` is the closed seven-value enum. `transition_root` must bind the previous authority root and every row field. |
| `authority_allowed_writers` | One row per allowed writer root for an authority epoch. | Key `(epoch_index, writer_profile_root)`. The reconstructed tuple is sorted by `writer_profile_root`; duplicates and unknown epochs reject. |
| `publication_atoms` | The scalar fields of `PublicationAtomV1`, including its context-bound copies. | Primary key `sequence`; unique `commit_id` and `nullifier_root`; sequence is contiguous from one. `expected_pre_root` must equal genesis or the prior atom's `post_state_root`. |
| `publication_evidence` | The seven rows generated by `_evidence_rows` for every atom. | Unique `(commit_id, kind)`. `kind` is the closed set `command`, `response`, `receipt`, `decision`, `bundle`, `replay`, `authority`. Rows are sorted by the model's tuple order. |
| `publication_nullifiers` | The rows generated by `_nullifier_rows`. | Primary key `nullifier_root`; `commit_id` and `fingerprint` must equal the referenced atom. Rows are sorted by the model's tuple order. |
| `publication_outbox` | One row per `OutboxEffectV1`, generated by `_outbox_rows`. | Primary key `effect_id`; unique `(commit_id, ordinal)`; `ordinal` is contiguous from zero within each atom and the row is bound to its atom. Rows are sorted by the model's tuple order. |
| `delivery_acks` | One row per `DeliveryAckV1`. | Primary key `effect_id`; at most one row per effect. Destination, payload, adapter profile, and idempotency root must equal the committed outbox projection. |

The model types and their checks are at
`src/core/fcis_durable_retraction.py:180-247`, `:341-395`,
`:587-777`, and `:779-847`. A production schema must refine the same closed
widths and collection bounds; widening a database type does not widen the
accepted research domain.

The `fingerprint` and `atom_root` properties are not additional atom fields.

```text
fingerprint = H(sequence, commit_id, command_root, expected_pre_root,
                post_state_root, writer_profile_root,
                deployment_config_root, verifier_profile_root,
                authority_epoch_index, authority_state_root, nullifier_root,
                response_root, receipt_root, decision_root, bundle_root,
                replay_root, outbox_root)
atom_root   = H(sequence, fingerprint)
```

The source implementation is at `:249-282`. A future cached fingerprint or
atom-root column is a `derived-root` cache and must be recomputed from the
complete row set at commit and reopen.

## Fixed-point relation

The canonical writer is `encode_history` at `:968-997`. It writes:

```text
snapshot_meta
authority_epochs + authority_allowed_writers
publication_atoms
publication_evidence = _evidence_rows(atom_rows)
publication_nullifiers = _nullifier_rows(atom_rows)
publication_outbox = _outbox_rows(atom_rows)
delivery_acks
snapshot_root = _snapshot_root_without_cache(complete_layout)
```

The reopen relation at `:1000-1106` must be refined as the following exact
sequence:

1. Reject wrong exact types, invalid widths, invalid enums, invalid collection
   shapes, invalid row budgets, or malformed roots.
2. Recompute the snapshot root from the complete physical layout and compare
   it with the stored root.
3. Recompute every evidence, nullifier, and outbox projection and require
   exact tuple equality, including order and cardinality.
4. Reconstruct `AuthorizedHistoryV1` from the header, authority rows, atom
   rows, and acknowledgment rows.
5. Require the stored current-state cache to equal the reconstructed state.
6. Re-encode the reconstructed history and require exact full-layout equality.

This means each of the following is a fixed-point failure: a missing row, an
extra row, a duplicate row, a crossed reference, a stale context copy, a
wrong enum, a reordered collection, a stale root, or a valid root attached to
the wrong transition. A selected state root alone is insufficient.

## Boundary retained for H02 and H07

The current `PublicationAtomV1` has no `anf_root` field. H02 names an ANF root
as part of the atomic publication payload. H01 therefore records an explicit
unresolved boundary rather than silently identifying `anf_root` with
`atom_root`, `bundle_root`, or `replay_root`:

```text
anf_root -> no current PublicationAtomV1 field; H02/H07 must add a checked
            proof-context relation or document an exact external table and
            its atomic membership before a concrete transaction can claim it.
```

The same rule applies to any production receipt, proof context, or response
blob that is represented only by a digest in this research model. A digest
column does not prove that the referenced bytes are stored, authenticated, or
atomically published.

## H01 nonclaims

- This matrix is a logical refinement contract, not a SQLite, PostgreSQL, or
  RocksDB implementation.
- No transaction, isolation level, WAL/fsync setting, crash hook, or recovery
  harness is implemented by H01.
- The matrix does not prove that a production caller supplies authenticated
  atoms or that a production adapter enforces the relations.
- The `anf_root` relation remains open for H02/H07.
- M6 remains unmounted and non-promotable; H02-H08 and the later outbox,
  migration, no-bypass, and whole-system obligations remain open.
