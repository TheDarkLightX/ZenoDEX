# ZDEX hyperdeflation burn RISC0 guest

This research-only workspace is a source-level proof candidate for one exact
ZDEX purchase-to-burn leaf transition. The guest consumes bounded canonical
`ZDEXHyperdeflationBurnGuestInputV1` bytes, reruns the Rust hyperdeflation
transition, applies the exact purchase-to-burn refinement, and commits the
canonical `ZDEXBurnJournalV1` only when both checks accept.

The refinement requires the validated, externally supplied purchase journal
fields to match the accepted burn transition and requires the transient purchased-ZDEX bucket to
drain exactly to zero. The committed journal binds chain, deployment, profile,
writer epoch, route and command occurrence, tokenomics module release, burn
policy, buyback budget occurrence, authorized quote input, purchase occurrence,
asset, burn bucket, burned amount, owned amount, supply, tokenomics burn-substate
roots, route-context root, and effect-plan root.

Fast placeholder-safe replay:

```bash
RISC0_SKIP_BUILD=1 CARGO_INCREMENTAL=0 CARGO_PROFILE_TEST_DEBUG=0 \
  cargo test --locked --workspace
RISC0_SKIP_BUILD=1 CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 \
  cargo clippy --locked --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

Real-proof smoke target, with no recorded receipt yet:

```bash
cargo test --locked -p zenodex-zdex-hyperdeflation-burn-risc0-host \
  --test real_proof \
  real_zdex_hyperdeflation_burn_proves_the_exact_journal \
  -- --ignored --nocapture
```

This workspace is unmounted and has no publication authority. No active
economic profile selects its image and no settlement writer accepts its output.
The placeholder method generated by `RISC0_SKIP_BUILD=1` is rejected by proving
and verification calls.

A real receipt would establish execution of this exact burn leaf under its
pinned guest image. It would not authenticate the purchase receipt by itself,
establish fee allocation, compose the Spot and tokenomics receipts, prove an
epoch, prove global bucket inclusion, establish durable replay or atomic
publication, or establish whole-economy safety or production readiness. Those
claims require the governed route/profile binder, the remaining proof fabric,
and ZenoLedger commit evidence.

This adapter also does not establish the release `max_cycles` ceiling. The
current receipt-verifier port receives image and journal bindings without an
authenticated cycle count. Activation remains blocked until a release-selected
resource bound is enforced in the guest/proof statement and checked by governed
admission.
