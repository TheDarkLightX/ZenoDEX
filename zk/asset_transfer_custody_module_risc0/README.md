# Custody-complete ASSET transfer preflight candidate

This workspace currently contains a native `shared` crate. It prepares the
custody-complete transfer result and canonical V1 journal for a future, separately
qualified execution release. It has no RISC0 guest target, measured image, receipt
verifier, release selection or publication capability.

The two preparation entry points statically invoke the custody-complete wrapper.
Raw input is bounded before decoding, decoded into the existing closed V1 type,
and checked for exact canonical encoding before typed validation. Economic
rejections return their existing exact error code without a journal. Acceptance
returns the validated full result and bounded canonical journal bytes.

The historical shared crate supplies the existing input encoder, error and result
types. Its execution entry points retain their historical semantics. A prepared
result remains ordinary caller-constructible data and supplies no authority.

## Native verification

Use the installed Rust 1.90.0 toolchain. From this directory:

```sh
cargo +1.90.0 generate-lockfile --offline
cargo +1.90.0 test --workspace --locked --offline -j 2
cargo +1.90.0 clippy --workspace --all-targets --locked --offline -j 2 -- -D warnings
cargo +1.90.0 fmt --all -- --check
```

The lockfile was generated by the first command; it was not edited by hand. The
implementation uses existing local dependencies and the existing pinned
`serde_json` dependency. Native verification may reuse an existing
`CARGO_TARGET_DIR` with `CARGO_INCREMENTAL=0` to limit disk use.

Six tests passed on September 5, 2026. They exercise the retained seven accepted
and three rejected custody fixtures, including complete physical totals, maximum
`u128` totals, full accepted-value equality, custody frames, canonical journal
bytes and exact economic rejection. Boundary tests cover empty input, malformed
input at the byte limit, oversized input before decoding, unknown fields,
noncanonical bytes, canonicality-before-ABI rejection and projection overflow.
Clippy with warnings denied and formatting checks passed.

The integrator corrected two compilation errors in the implementation-agent's
test draft: a missing journal type annotation and a borrowed temporary. The
integrator also required nonempty fixture cardinalities and added the exact input
limit and rejection-precedence controls. The agent did not run builds.

An isolated semantic mutant replaced both occurrences of
`transition_asset_transfer_lane_module_custody_v1` in `shared/src/lib.rs` with
`transition_asset_transfer_lane_module_v1`. With unchanged tests, it compiled and
failed `zero_custody_matches_legacy_preflight_and_nonzero_custody_differs` because
legacy acceptance cannot satisfy the nonzero-custody result. The production
source stayed unchanged during that isolated check.
