# Neutral tie-break (prototype) — roadmap item 1a

Grinding-resistant, deterministic, replayable tie-break for ZenoDex settlement
ordering, **with a byte-identical Python + Rust pair**. **Isolated prototype —
not wired into any consensus path.**

Derived from `internal/ZENODEX_RESEARCH_BUILDOUT_ROADMAP_2026-06-18.md` item 1a and
findings H12 (Algorand VRF sortition), H14 (RANDAO last-revealer), H15 (Aequitas)
in `internal/RESEARCH_LITERATURE_OPTIMIZATIONS_2026-06-18.md`.

## Problem (grounded in the current tree)

ZenoDex breaks ties on **participant-chosen identifiers**, which the participant
can grind (pick a small/favorable id to win ties deterministically):

| Surface | Current identifier tie-break | File |
|---------|------------------------------|------|
| Spot batch clearing | greedy key `candidate_key = (b, -a, str(intent_id))` — final component is `intent_id` | `src/core/batch_clearing_ordering.py:211` |
| Proof-mining / improvement-bounty routing | winner ties resolve on `miner_id` in the route selector | `tools/gpu_jobs/improvement_bounty_round_route_v1.py:87,194` |
| Sealed-bid (equal-remainder leftovers) | `_sealed_bid_output_key` ranks equal pro-rata remainders by `bidder_id` + `commitment` | `src/core/sealed_bid_auction.py:135,175` |

Sealed-bid already uses **pro-rata largest-remainder** for the bulk of
oversubscription (so it is *not* a naive winner-hash auction), but the
**equal-remainder leftover** ranking still falls back to participant identifiers
(`bidder_id`/`commitment`) — so it is a grindable surface too, not exempt.

## Fix (this module)

Replace only the identifier component of the tie-break with a key derived from a
per-batch **seed**, using **collision-free length-prefixed framing**:

```
framed(x)          = u64_be(len(x)) || x
tiebreak_key(s, id) = sha256( framed(domain_sep) || framed(s) || framed(id) )
```

Length-prefixing is load-bearing: a naive `domain || 0x00 || seed || 0x00 || id`
framing collides (`(b"a\0b","c")` vs `(b"a","b\0c")`). The prototype and its tests
pin the exact pair as distinct.

- **Deterministic + replayable:** a pure function of `(seed, id)` — no live
  randomness; same inputs replay to the same order (consensus-safe).
- **Grinding-resistant:** given a seed the participant cannot predict when they
  pick `id`, the win probability over identifier choices is ~uniform. The tests
  show the current lex rule has a **100%** grind win-rate while the seeded rule
  holds a grinder to ≈ `1/k` (fair, observed 0.133 vs fair 0.125) even when they
  optimize their id offline.
- **Minimal drop-in:** `ab_key_seeded` preserves the first two (objective)
  components of the greedy key byte-for-byte and changes only the third. (The
  greedy key at line 211 *minimizes* `(b, -a, …)`; this prototype does not
  re-judge that objective direction — it only swaps the grindable identifier.)

## Composition requirement (NOT solved here — load-bearing caveat)

Grinding-resistance holds **only if the seed is, at production time, both
(a) unpredictable / unavailable until all identifiers are locked, and
(b) unbiasable.** A public or readable seed fixed *before* identifiers are chosen
is still grindable; a seed the last actor can selectively reveal/withhold (RANDAO
last-revealer, H14) is biasable. An unbiasable, late-bound seed must come from a
**VRF**, **commit-reveal-with-punishment**, or **threshold beacon** (H12/H13) — a
separate, composed obligation. ZenoDex has commit-reveal binding infra
(`src/kernels/dex/sealed_bid_commit_reveal_gate_v1.yaml`,
`src/tau_specs/recommended/commit_reveal_binding_guard_v1.tau`) to build on, but
no VRF/beacon yet. The seed source itself is now built — see **§Seed source**
(`seed_source.py`): commit-reveal-with-punishment, which makes withholding costly
and the seed binding + replayable, with the residual last-revealer bias documented
as *bonded, not eliminated* (a VDF/beacon is the further layer).

## Python + Rust parity

The primitive exists in both languages, proven byte-identical:

- `neutral_tiebreak.py` — Python reference (pure functions).
- `rust/src/lib.rs` — Rust shadow with the **same** length-prefixed framing.
- `parity_vectors.tsv` — golden vectors (`seed_hex⇥id_hex⇥key_hex`) generated by
  Python, covering edge cases (empty, embedded `0x00`, the collision pair, a
  full 0..255 seed byte, unicode ids).
- **Both sides assert against that one file:** Python (`test_python_matches_golden_vectors`)
  and Rust (`rust/tests/parity.rs`). Any divergence fails a test.

```
pytest experiments/neutral_tiebreak_v1/                              # 22 passed (tie-break + seed)
cd experiments/neutral_tiebreak_v1/rust && cargo test --offline      # 5 passed (tie-break + seed parity)
```

This follows the project's Python↔Rust differential-parity discipline up front,
not as an afterthought, so consensus promotion already has both implementations
locked to a shared contract.

## Seed source (`seed_source.py` + Rust parity)

The tie-break needs a per-batch seed that is unpredictable-until-locked and hard to
bias. `seed_source.py` provides it via **commit-reveal with punishment**:

- `commit(value, nonce)` — binding commitment (length-prefixed framed sha256).
- `derive_seed(commitments, reveals)` — verifies each reveal against its commitment;
  **non-/invalid-revealers are slashed and excluded**; `seed = sha256` over the
  canonical (id-sorted) verified `(id, value)` pairs. Deterministic / replayable;
  **fails closed** if no reveal is valid (no seed from zero entropy).
- `commit` and `seed_from_pairs` are mirrored byte-for-byte in Rust (`rust/`), locked
  to `commit_parity_vectors.tsv` + `seed_parity_vectors.tsv` (Python *and* Rust assert).

**Honest scope (H13/H14):** commit-reveal-with-punishment gives **binding**, makes
**withholding costly**, yields a **replayable** seed, and every included contributor
influences it (so a participant committing before others reveal cannot predict it).
It does **not** cryptographically eliminate the RANDAO *last-revealer* residual (an
actor holding final reveal slots still has a reveal-or-withhold choice) — here that
residual is **bonded** (each withholding costs a slash). Full elimination = compose
with a **VDF** over the commitments or a **threshold beacon**. Composed result:
`committed_seed_tiebreak_key(derive_seed(...).seed, id)` is a grinding-resistant
tie-break whose seed bias is bonded-bounded today, cryptographically eliminable with
a VDF/beacon — the remaining layer before wire-in.

## Wire-in plan (future increments, each Codex-reviewed)

1. **Seed source** — build/choose the unbiasable, late-bound per-batch seed
   (commit-reveal with punishment, or a VRF), explicitly defending against H14.
2. **Spot clearing** — swap the `str(intent_id)` component in
   `batch_clearing_ordering.py:211` for `committed_seed_tiebreak_key(seed, intent_id)`;
   keep the objective components unchanged. Characterization-corpus-first refactor
   (capture current order over a corpus → refactor → assert genuine ties only reorder).
3. **Proof-mining + sealed-bid** — same swap for the `miner_id` and the
   `_sealed_bid_output_key` (bidder_id/commitment) tie-breaks.
4. **Verification (Python *and* Rust, per CBC parity discipline)** — port the
   wired change to the Rust runtime shadow; differential test (Python ≡ Rust);
   ESSO model of the tie-break determinism/replay; runtime invariant that the
   seed is committed before the batch is fixed.

## Status

Isolated prototype. Not imported by any consensus path. No state mutation, no I/O,
pure functions only, in both Python and Rust.
