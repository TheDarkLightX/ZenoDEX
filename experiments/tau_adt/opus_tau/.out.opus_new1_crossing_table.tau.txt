tau> # ============================================================================

tau> # NEW TABLE KIND 1 - THE CROSSING TABLE (order book as two table values)

tau> # ============================================================================

tau> # Every table kind in the tutorials answers "is this row present?". A book

tau> # has to answer a RELATIONAL question instead: "do these two tables admit a

tau> # pair whose prices cross?" The construction keeps both sides as ordinary

tau> # table values over disjoint column streams and puts the matching law in a

tau> # THIRD value, a pure inequality with no rows at all:

tau> #

tau> #   BIDS  = { obpx=5, obq=10 } | { obpx=7, obq=4 }

tau> #   ASKS  = { oapx=6, oaq=8  } | { oapx=9, oaq=3 }

tau> #   LAW   = { obpx >= oapx }                    <- the matching law

tau> #   CROSS = BIDS & ASKS & LAW                   <- the matchable pair set

tau> #

tau> # Because bids and asks use different column streams their meet is the full

tau> # cartesian product, and the law selects the crossing pairs out of it. The

tau> # match is therefore not computed and compared - it is the value CROSS, and

tau> # "the book crosses" is the single decidable question CROSS != 0.

tau> #

tau> # ZenoDEX surface: the CLOB admission gate. An orderbook batch can be

tau> # admitted only if CROSS is non-empty, and the specific pair that clears is

tau> # the membership witness (b2) - both decided without a matching engine.

tau> # Run: tau -q < opus_new1_crossing_table.tau

tau> # EXPECTED-RESULTS: T T T T T F
