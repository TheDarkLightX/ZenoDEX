tau> # NEW TABLE KIND 2 - THE KEY-PROJECTED REGISTRY (a set table that is a set)

tau> # ============================================================================

tau> # A registry answers "has this key been used?". exp4 built one by joining

tau> # each admitted SPEND into the registry. That is not a set of keys - it is a

tau> # set of whole rows, and two rows can share a key while being disjoint as

tau> # values. The registry then misses the second one.

tau> #

tau> # The fix is a table kind, not a patch: registry rows are KEY-ONLY

tau> # projections, { onul = k }, and admission joins the KEY, never the row.

tau> # The payoff is a theorem quantified over ALL tau values, i.e. over every

tau> # spend an adversary can write, not over a list of cases we thought of:

tau> #

tau> #   for every spend x:  x != 0  and  x <= {onul=4}   =>   x & REGISTRY != 0

tau> #

tau> # ZenoDEX surface: the nullifier / replay-guard table. The same shape covers

tau> # any "used exactly once" set - order ids, intent hashes, epoch receipts.

tau> # Run: tau -q < opus_new2_key_registry_table.tau
